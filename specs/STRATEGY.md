# Brand, product scope, and message specification

## Required hierarchy

AI Ascension is the public identity; Ascension is the flagship developer product; The Climb is the audience-facing series. Retain the GitHub handle and aiascension.tech as the canonical website. Component names remain functional. The new brand repository is an operations/source home, not a second flagship or a replacement for the runtime architecture.

Use the central promise “Watch AI play. Inspect the run. Help it climb.” as the brand line, with factual adjacent copy identifying what can be watched or inspected now. “Open tooling for game-playing agents, starting with Slay the Spire 2” is the developer descriptor. Use “experiment” while broad reliability and support are not established. A source-controlled claim does not become independently verified just because it is in a README.

## Audiences and information order

Spectators need an understandable result, an actual video/report, and the next episode. Developers need a tested starting path, prerequisites, configuration, and boundaries. Researchers need exact versions, observation rules, intervention disclosures, attempts, budgets, and accessible evidence. Serve the audiences through distinct journeys, not through competing brands or homepages.

Lead with the experience. Place one short compatibility/evidence statement near each primary claim; link to full details. Preserve the technical rigor in documentation and run pages without making the entire brand a warning label. Do not hide important limitations in hover-only UI, footnotes too small to read, or inaccessible colors.

## Copy rules

Prefer observable verbs: ran, chose, failed, replayed, recorded, measured. Distinguish intended capability, implemented code, observed host result, independently reproduced result, and maintained release support. Never claim the mod is endorsed by Mega Crit or Valve. Credit third-party model providers by exact tested identifier when relevant; no assumed partnerships.

Use evidence-sensitive CTA rules: if no public video exists, “Read the run report”; if video exists, “Watch the run”; if an approved replay package exists, “Inspect the replay.” “Live” needs actual current broadcast status and an honest disconnected state. Model lineups are configurations with dates, not a permanent list of supposed top models.

The season “Road to the First Verified Win” must be reconciled with evidence at execution time. Do not overuse the same historical example. A recorded floor-17 defeat with 333 replayed settled actions can be a case study only with correct provenance and publication rights; a maintainer report can be cited without pretending the private video or trajectory is public.

## Naming and availability

Follow data/repository-map.json. Do not introduce Arena, Oracle, Sentinel, Atlas, or other competing mini-brands. Before public rollout perform a bounded obvious-collision check of the selected wordmark, symbol, handle usage, and domain representation. Record search date, sources, scope, and unresolved issues. This check is not legal trademark clearance. Do not file registrations or buy domains without explicit authority.

## Content source of truth

Implement versioned structured copy and capabilities. Include a display label, source ID, source revision, observed date, evidence kind, verification actor, public artifact availability, supported configuration, and review status. Generate current headline support panels and README summaries from it. Preserve history rather than overwriting old evidence.

## Deliverables and acceptance

A complete brand guide includes positioning, naming grammar, product boundaries, typography references, colors, logo use, dark/light modes, accessibility rules, voice, message examples, disclosure placement, component descriptions, and claim vocabulary. Test comprehension using actual external participants when available; otherwise report internal heuristic review separately and supply the test protocol. Do not invent participants or test scores.

## Mandatory artwork source

All new artwork, including promotional images, exported diagrams, card artwork, icons, and creative revisions, follows `art/ASTRA_GPT_IMAGE_2_POLICY.md`: an actual `gpt-6-astra` author writes each final prompt and `gpt-image-2` generates the art. Functional HTML/CSS/data and approved real evidence are separate. Runtime serving uses already approved images with no implicit model calls. Missing art-model access blocks that asset, never authorizes code-drawn or reused-art substitutions.
