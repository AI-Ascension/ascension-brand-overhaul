# Source register and freshness

The strategy is the preceding user-selected overhaul. `data/source-register.json` distinguishes files read during this package preparation, evidence already returned in the preceding conversation, and sources that are only pointers for later verification. Blob SHAs identify file contents, not repository HEAD commits. The execution root must resolve default branches, stable repository IDs, exact commit SHAs, and current open PRs before making changes.

This package does not re-run game campaigns, validate a live subscription form, clear a trademark, test the user's model entitlement, or assert that a current site matches a repository branch. It contains a source-aware assignment, not certification of those facts. Refer to source IDs in implementation decisions and retain full URLs and access dates in the execution evidence ledger.

Source facts and proposals must stay separate. Existing glyphs, banners, identity art, and font references are located in the existing site repository; they are not embedded in this ZIP. Fetch only what the executor is permitted to use. The partial STATUS read must not be mistaken for its latest appended section. Inspect the complete current record.
