## Findings

### W01-W06-MKT-01 — EXP-07 uses an event that the frozen collector rejects (medium, experiment-blocking)

`marketing/experiments.json:325-368` defines EXP-07's primary event as `correction_open`; its numerator additionally requires submission of a valid source/revision pointer (`:333-336`). The marketing test's allowlist accepts this name (`tests/test_marketing_experiments.py:39-49`), but the frozen event schema enum contains only the 13 names at `schemas/event.schema.json:11-16`, and `analytics/event-contract.json:9-126` has no `correction_open`. `publisher/events.py:38-42,74-80` consequently rejects the event. A synthetic validation probe at the frozen head returned `SchemaValidationError`: `correction_open` is not one of the permitted event names.

EXP-07 therefore cannot collect the metric under the approved event pipeline. Its current `unobserved` state is honest, but the experiment is not executable until the definitions agree. Either change the experiment to measure an existing event with a matching numerator, or add a separately reviewed correction-submission event across the schema, event contract, runtime validator, privacy rules, and marketing tests. If opening guidance and submitting a correction are intended to be different events, specify both and do not use `correction_open` to claim a valid submission.

### W01-W06-MKT-02 — Secondary proxy names have no declared contract mapping (medium, measurement readiness)

The `secondary_metrics` arrays use `return_visit_proxy` and `contributor_repeat_proxy` (`marketing/experiments.json:91-94,141-144,241-244,292-295`). They are neither event names in `schemas/event.schema.json:11-16` / `analytics/event-contract.json:9-126` nor metric IDs in the declared metric registry (`analytics/event-contract.json:132-186`, which declares `repeat-engagement-proxy` instead). The dashboard description permits a consented coarse-cohort repeat proxy (`analytics/dashboard-spec.md:19-24`), but W06 does not define how either marketing identifier is derived, which source events feed it, or what denominator and window apply. The marketing test allowlist currently masks this gap by calling these names approved event vocabulary (`tests/test_marketing_experiments.py:39-49`).

Before any experiment starts, replace these labels with declared metric IDs or add a reviewed derived-metric mapping that names source events, cohort/consent rules, denominator, window, exclusions, and absent-data behavior. Add a cross-file check so an unsupported event or unmapped derived metric cannot pass as an approved experiment field. Keep all results unobserved until that mapping and an enrolled production scope exist.

### W01-W06-MKT-03 — W06 execution receipt records the wrong full-suite count (medium, provenance)

`execution/w06-implementation.json:202-208` records the targeted result correctly as 9 tests but says full discovery passed 60 tests. Running its recorded command against the exact frozen revision produced **170 passing tests**. The status is green, but the recorded count is not reproducible and understates the validation actually performed. Update the execution receipt through the root coordination process with the exact frozen command and count; retain the source revision and independent-review state alongside it.
